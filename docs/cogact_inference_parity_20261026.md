# CogACT 训练与 RobotControl 推理一致性审计

2026-10-26 核对了 CogACT 关节训练配置、数据处理、在线推理路径，以及 RobotControl-G1 `b37c683` 的客户端和动作解释器。主 agent 与独立 subagent 交叉审计，35 项 CPU 测试通过。按用户要求取消本地 serve；未运行完整模型 GPU 推理，未操作训练 Pod。

结论：**已核对的动作表示、归一化、条件构造和 attention 规则一致；原始 RobotControl 客户端仍有图像传输、历史观测和回合重置差异，尚不能称为完整端到端一致。**

## 已确认的一致项

| 项目 | 训练与推理约定 |
|---|---|
| 状态与槽位 | 当前实测状态，顺序为左臂 7 关节、左夹爪、右臂 7 关节、右夹爪；映射至 80 维的 `0–6,16,40–46,56` |
| 动作语义 | 32 步绝对关节目标与夹爪目标。训练标签来自下一帧实测关节和当前帧夹爪命令；输出不与当前关节相加 |
| 夹爪尺度 | 训练实测状态除以 120；RobotControl 已做该转换，服务不重复除。输出夹爪截断到 `[0,1]`，控制端 scale factor 应设为 `1.0` |
| 归一化 | 使用匹配的全量 `normalization.json`；状态 z-score（减均值、除标准差）并截断至 `[-5,5]`；预测按 action 统计反归一化 |
| 服务内图像处理 | 头部、左腕、右腕各缩放至 `192×256`；Wan 画布为 `384×256`，视觉语言模型使用同一组缩放后的视图。任务 3173 需对应头部裁剪 |
| 文本与视觉语言条件 | 相同任务 prompt、视角名、图像、有效性掩码和当前状态 token；T5 填充位置的向量归零，但 context mask 保持全 True |
| 动作生成 | RTC 关闭，action flow matching 调度器 `shift=1`，默认 10 次去噪；严格加载全部可训练模块 |

训练有未来视频监督，推理只使用可观测条件。独立测试比较真实 attention mask 构造函数：移除训练专用未来视频 token 后，其余 token 之间的读取规则与在线推理逐元素一致；保留的 query 不依赖被移除的未来 token。这证明条件可见性一致，不等于完整模型输出已做数值对比。

## 已修复的问题

可选设备拆分时，RynnBrain 输出原本会先与策略设备上的状态 token 拼接，导致跨 GPU 设备不匹配。现在在拼接前将视觉语言 context 和 mask 移至策略设备。单设备默认路径保持相同语义。

同时核对了 T5 独立设备编码的条件语义，以及 VAE 普通统计张量、VLM device/dtype 的放置。`--text-device cpu` 和 `--encoder-device` 可用于后续部署，但本次 CPU 测试不能证明跨 GPU 或 5090 已可运行。

## 部署前仍需对齐的三项

1. **图像传输。** 原始客户端先缩至高 240 再 JPEG 编码，离线训练没有这一步；服务内处理相同也不能还原丢失的像素。需要客户端传递与训练视野一致的图像，或单独评估这项偏差。
2. **真实历史。** 训练使用回合首帧和 `t−32` 历史帧。原客户端只在推理时传当前观测；缺少历史时服务会屏蔽该条件，默认请求到达时间也只是 30 Hz 时间轴的估计。精确对齐需真实 `frame_index` 和中间观测，可经 `/api/observe` 提交。
3. **回合重置。** 原始 `CogACTPolicy.reset()` 是空操作。同一句指令重试必须显式调用 `/api/reset` 或发送 `reset=true`，否则会沿用上回合首帧。

接口格式与调用示例见[部署说明](cogact_robotcontrol_serve.md)。这些差异需在客户端接入时处理；本次没有修改外部 RobotControl 仓库。

## 验证证据与边界

35 项测试覆盖动作映射、归一化、图像处理、历史与 reset、原始 RobotControl HTTP 客户端和解释器联调，以及真实 attention/视觉语言条件构造函数。完整神经网络和昂贵的冻结编码器使用替身，未验证完整 checkpoint 的 GPU 数值误差、显存、延迟或实机效果。SDPA 与训练 Flex attention、在线文本编码与训练缓存也不承诺逐位相同。
